# mood-cube-blocks

micro:bit v2 用 MakeCode 拡張機能。フィジェット作品「mood cube」のハードウェア抽象層を提供する。

## 何を提供するか

5 つの namespace に分かれている。

- `cubeTouch`: 触感キューブの入力 (上面判定、ピン刺し検知)
- `cubeGrip`: 握りつぶしキューブの入力 (圧力読み取り、握り始め/離した/最大到達 等のイベント)
- `cubeLight`: フルカラー LED (PL9823) の発光制御。両キューブ共通
- `cubeVibe`: 振動モーターの制御。両キューブ共通
- `cubePair`: ペアの相棒キューブとの連動制御。`cubeTouch` と `cubeGrip` の入力イベントは相棒側にも自動で届くので、相棒のキューブで起きた入力に自分のキューブが反応する書き方ができる

体験のロジック (どの色を何に対応付けるか、どんなときに振動させるか等) はこの拡張には含まれない。アプリ層として MakeCode プロジェクト側で組む。

電力管理 (無操作時の自動 deepSleep と、ボタンや動きでの起床) は拡張内部で透明に行うのでアプリ層は意識しなくてよい。

## 使い方

MakeCode の拡張機能インポートで本リポジトリの URL を指定すると、上記 5 カテゴリがブロックパレットに追加される。各キューブ用に MakeCode プロジェクトを 1 つずつ作り、必要なブロックを組み合わせて挙動を定義する。

## 想定する作品

触感キューブと握りつぶしキューブの 2 つでペアになるフィジェット作品。それぞれ別の micro:bit に本拡張をインポートしたプロジェクトを書き込み、ハードウェアと組み合わせて動かす。

要件などドキュメントは [docs/README.md](docs/README.md) を参照。

## 注意

ブロックパレットに `Neopixel` カテゴリが表示されるが、本拡張は発光制御を `cubeLight` にラップしているため、子供のアプリ層は `cubeLight` のブロックだけを使うこと。`Neopixel` 側のブロックを直接呼ぶと cubeLight の内部状態と整合しなくなる。
