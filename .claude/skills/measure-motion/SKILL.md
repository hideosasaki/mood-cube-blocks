# モーションイベント計測

加速度差分の時系列波形を取り、cubePower.tsのモーション判定 (PICKUP/PUTDOWN) のパラメータを検証する手順。静的な状態の統計ではなく「イベントが何窓続くか」を見るのが目的。実例: 2026-07-13に机振動と持ち上げの分離を計測し、2窓確認方式の根拠にした (docs/measurements/2026-07-13-motion-events.csv)。

## シリアルではなくフラッシュ記録を使う

時系列解析は欠損に弱い。シリアル (DAPLink CDC) は条件が良くても半分程度、MakeCodeのWebUSB接続が残っていると9割欠ける。欠けた窓は「静止」と「未受信」の区別がつかないので、モーションイベント計測は必ずflashlog (フラッシュ記録、欠損ゼロ・タイムスタンプ付き) で行う。

## 手順

1. flashlogファームを焼く。`cd tools/measure/flashlog && pxt build` して、flash-microbitスキルの手順でpyOCD書き込みする。mo列 (20msごとの3軸差分和、cubePower._accelDiffと同じ計算) が記録される
2. シナリオを設計する。静的状態ではなく「15秒の記録中に同じ動作を2〜3秒おきに繰り返す」形にする (例: 机にものを置く、持ち上げて置く)。ベースライン (無操作) も必ず1本入れる
3. ユーザーに操作を依頼する。A+B同時押しで全消去 (`C`表示) → Aでシナリオ開始 (番号表示) → Bで停止 (小さい四角) → Aで次のシナリオ、の繰り返し。加速度計測はUSB挿したままでよい (P0タッチと違い接地の影響なし)
4. MICROBITドライブから `MY_DATA.HTM` をコピーして解析する

   ```sh
   python3 tools/measure/analyze-motion-events.py MY_DATA.HTM
   ```

   シナリオごとに、5サンプル窓の最大値系列 (= `_stepMotion` が見る値) とイベント (窓値がSTILL_THRESHOLD以上の連続区間) の窓数・ピーク・系列が出る

## 結果の読み方と注意

- フラッシュ書き込み遅延で実効サンプリングは20ms指定でも50ms前後になる。出力のrate/gapで必ず確認する
- そのため差分の絶対値はファーム実動作 (20ms) より大きく出る。しきい値の絶対値をこの計測から直接決めない。「何窓続くか」の構造比較に使い、定数の最終確認はロジック実装後に実機 (20ms動作) で行う
- 生データは `docs/measurements/<日付>-<条件>.csv` に変換して保存し、判定変更の根拠としてcommitする (HTMからのCSV抽出はanalyze-motion-events.pyと同じ正規表現でよい)
- 解析スクリプトのSTILL/MOTION定数はcubePower.tsの写し。拡張側を変えたら揃える
