# モーションイベント計測

加速度差分の時系列波形を取り、cubePower.tsのモーション判定 (PICKUP/PUTDOWN) のパラメータを検証する手順。静的な状態の統計ではなく「イベントが何窓続くか」を見るのが目的。実例: 2026-07-19に机への衝撃の残響窓数を計測し、確認3窓方式の根拠にした (docs/measurements/2026-07-19-motion-shock.csv)。

## フラッシュ記録は使えない。リアルタイムシリアルで行う

MakeCode datalogger (フラッシュ記録) は書き込みがハングするバグで機能しない (2026-07-19、握りキューブ個体でも確認。ハング中も他のfiberは生きるので記録だけ静かに消える)。計測は必ずシリアルのリアルタイム送信で行う。

シリアルの欠損対策は次の2つで足りる。

- 20ms生値を送らず、100ms窓の最大値 (= `_stepMotion` が見る値そのもの) を10Hzで送って帯域を1/5にする
- 各行にタイムスタンプを載せ、受信側で行間隔から欠損を検出する

この方式で2026-07-19は4シナリオ×20秒を欠損ゼロで取れた。

## 計測ファーム tools/measure/serialmotion

`mo:<runningTime7桁ms>:<シナリオ番号1桁>:<窓最大値4桁>` の固定長行を10Hzで送る。筐体に入れたままボタンに触れない状況を想定し、シナリオはスピーカーの合図で自動進行する (起動15秒後から、ビープN回=2秒後にシナリオN開始で各20秒、最後に低い長め音)。ビープ中はシナリオ番号を0にするので、スピーカー振動の混じった行は解析でsc=0を捨てれば除外できる。

注意: 20ms周期ループに `basic.forever` を使わない。1周ごとに約20msの追加yieldが入り実効40ms/tickに間延びする (2026-07-19実測)。`control.inBackground` + `while(true)` + `basic.pause(20)` で組む。

## 手順

1. `cd tools/measure/serialmotion && pxt build` して、flash-microbitスキルの手順でpyOCD書き込みする。書き込み直後にシーケンスが勝手に走らないよう `pyocd cmd -t nrf52833 -c halt` で止めておく
2. シナリオを設計する (ベースライン無操作を必ず1本入れる)。ユーザーに合図と操作の対応を伝え、準備の返事をもらう
3. `python3 tools/measure/serialread.py 150 > <capture>.txt` をバックグラウンドで開始してから `pyocd cmd -t nrf52833 -c reset` で走らせる
4. 受信完了後に解析する

   ```sh
   python3 tools/measure/analyze-motion-events.py <capture>.txt
   ```

   受信キャプチャと保存済みCSVのどちらも読める。リセット前の残留行の除去とsc=0の除外はスクリプトが行い、シナリオごとにイベント (窓値がSTILL_THRESHOLD以上の連続区間) の窓数・ピーク・系列が出る

## 結果の読み方と注意

- 生データは `docs/measurements/<日付>-<条件>.csv` (time_ms,scenario,mo_win100) に変換して保存し、判定変更の根拠としてcommitする
- 解析に使うSTILL/MOTION定数はcubePower.tsの写し。拡張側を変えたら揃える
- 誤発火の再現計測は、実際に誤動作した筐体・机・操作で行う (筐体の質量や脚で振動の伝わり方が変わる)
